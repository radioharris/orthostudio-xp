# Modifications to Triangle4XP.c (notice required by Triangle's licence)

Base: `Utils/src/Triangle4XP.c` of Ortho4XP (commit `d3bf078`, "Last modified : Feb 21st
2024"), itself Triangle 1.6 modified by Oscar Pilote (his changes are delimited in the source by
`Start of : Added for Triangle4XP` / `End of : Added for Triangle4XP`).

Every OrthoStudio XP change is delimited by `Start of : Added for OrthoStudio XP` /
`End of : Added for OrthoStudio XP` (or `Modified for OrthoStudio XP`) comments. Apply order and
content, September 2026:

1. **Header**: one line after "Last modified", pointing to this file.
2. **`#include <stdint.h>`** after `<string.h>` (fixed-width integers of the binary layouts).
3. **Forward declarations** of `osxp_malloc()` and `osxp_read_exact()` after the `readline()`
   / `findfield()` prototypes (they are used by `formskeleton()`, defined later in the file).
4. **`struct behavior`**: new field `int binary_io`.
5. **`parsecommandline()`**: `b->binary_io = 0` initialisation; new switch letter **`b`**
   (`binary_io = 1`); after `usesegments` is computed, `-b` combined with `-r` prints an error
   and exits with status 1 (mesh reconstruction reads a text `.ele`, not supported in binary).
6. **`syntax()`**: two help lines documenting `-b`.
7. **`main()`**: the `.alt` raster (`nxdem * nydem` float32) and the `.weight` raster
   (`1001 * 1001` float32) are read with **one `fread` each** instead of one `fread` per
   sample; a short read is now an error (`triexit(1)`) where it previously left the tail of the
   array uninitialised. The unused `dummy` variable is removed.
8. **New static helpers** at the start of the "File I/O routines" section: `osxp_malloc()`,
   `osxp_read_exact()`, `osxp_write_exact()`, `osxp_check_magic()`, the three 8-byte magics
   `OSXPNOD1`, `OSXPPOL1`, `OSXPELE1`, and a compile-time error if `SINGLE` is defined (the
   layouts require `REAL == double`).
9. **New functions** (non-`TRILIBRARY` builds only):
   * `readnodes_binary()`: same effects as `readnodes()` (vertex pool, `firstnumber`,
     bounding box, `readnodefile`, error conditions) from an `OSXPNOD1` / `OSXPPOL1` file.
   * `readholes_binary()`: same effects as `readholes()` (holes, regions only when
     `regionattrib || vararea` and not refining, `polyfile` closed).
   * `writenodes_binary()`: same values as `writenodes()` in the non-refining case (clamped
     x, y; `altitude()`; `set_normal()`; input attributes; boundary markers unless `-B`),
     written as float64/int32 instead of `%.17g` text; numbers the vertices like `writenodes()`.
   * `writeelements_binary()`: same corner numbers and attributes as `writeelements()`.
10. **Dispatch**: `readnodes()`, `readholes()`, `writenodes()` and `writeelements()` call the
    binary variant and return when `b->binary_io` is set. In `formskeleton()`, the binary path
    reads the segment count, endpoints and markers of the `OSXPPOL1` file in three `fread`
    calls before the insertion loop, then feeds the unchanged insertion code; buffers are freed
    after the loop (and on the early return when there are no triangles).

Not changed: `triunsuitable()`, the curvature map (`hme`), `altitude()`, `set_normal()`, the
Delaunay, segment insertion, hole carving, attribute plague and quality enforcement code, all
text readers and writers, the `# Generated by` trailer of text outputs, exit codes and
messages of the text mode.

Known upstream issues deliberately left as they are (see `docs/specs/mesh-triangle-io.md`):

* `parsecommandline()`: `scaly2 = scalx * scalx;` (should be `scaly * scaly`). Harmless:
  `scaly2` is never read anywhere in the file, only `scalx2` is (in `triunsuitable()`).
* Behaviour depends on the compiler's floating-point contraction (fused multiply-add on
  arm64): see `README.md`, "Build".
